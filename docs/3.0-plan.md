# survival 3.0 breaking-change plan (draft for approval)

## Purpose and how to use this document

The owner's rule for 2.x: changes are additive only. We may add names, keys and keyword aliases, deprecate with a warning, and document. Anything that would break an existing caller waits for 3.0 and needs approval first. That includes removing or renaming a name, changing what a key or attribute means, changing a return type, and removing a public Rust item.

This document lists the breaking clean-ups the 2026-10-11 audit found that still reproduce. The owner approved every item on 2026-10-12. The breaking changes ship together in 3.0.0 without a 2.x deprecation release, with a migration guide. Nothing here has been started. Each item says what 2.x can do now, so that most of the 3.0 work becomes removing names that have already been deprecated.

- **Evidence.** Line references point to the `fix/audit-api-additive` worktree at `e9b1e29c` (Python and Rust 2.0.0, survivalr 0.1.0). "Repro" lines were run on that tree's built extension.
- **Deprecation conventions** (proposed for every item):
  - Python: `DeprecationWarning` with `stacklevel=2`, worded "`<old>` is deprecated and will be removed in survival 3.0; use `<new>`." Use `FutureWarning` when a name stays but its meaning changes. One shared helper: `survival._deprecation.warn_3_0(old, new)`.
  - R bridge: `.Deprecated("<new>")` with the same message.
  - Rust: `#[deprecated(since = "2.1.0", note = "...")]`.
  - Every deprecation also goes into a "Deprecated (removed in 3.0)" section of `CHANGELOG.md` and a migration table in `docs/r-compatibility.md`.
- **Assumption for the owner to confirm.** Bug fixes that move results to R's values count as fixes, not breaks, as in PR #734 (character columns as factors, `Factor` dataset columns). None of them is listed here.
- **"Lockstep"** means the R bridge (`r/survivalr`) changes in the same release, so R users see no difference.

## C1. `survival.residuals` shadows R's `residuals` generic

**Status:** needs a break.

**Evidence:**
- `python/survival/__init__.py:41` maps `residuals` to the kernel module `python/survival/residuals.py` (`coxmart`, `agmart`, `SurvregResiduals`).
- Repro: `survival.residuals(fit)` raises `TypeError: 'module' object is not callable`. `survival.r.residuals(fit)` works, as do root `coef`, `vcov`, `predict` and `fitted`.
- README.md:461-464 documents the workaround.

**(a) 3.0 end state:** `survival.residuals` is `survival.r.residuals`. The three kernels live in `survival.kernels` (C12).

**(b) 2.x prep:**
- Give `residuals.py` a `ModuleType` subclass whose `__call__` forwards to `survival.r.residuals`, so `survival.residuals(fit)` works in 2.x.
- Serve the three names through a module `__getattr__` that warns: "survival.residuals.coxmart is deprecated and will be removed in survival 3.0; use survival.kernels.coxmart."
- Fix the README.

**(c) Affected:** Python users who import the module or its three names. R bridge: `.residuals_attr("agmart")` (`r/survivalr/R/bridge.R:121`), lockstep. Rust: none.

**(d) Size:** S. Files: root `__init__.py` and `.pyi`, `residuals.py`, `bridge.R`, README, `python/tests/test_binding_contract.py`.

**(e) R fidelity:** improves it.

## C2. Summary and anova results

**Status:** needs a break for the meaning and type changes. The additive parts are under (b).

**Evidence:**
- **survreg summary.** `model_summary(survreg_fit)['coefficients']` is a list of row dicts `{'name','coef','se','naive_se','z','p'}` (`r/_survreg.py:1764,1814`), and there is no `'table'` key. In R, `$coefficients` is the named vector and `$table` the matrix.
- **coxph summary.** Coefficient rows use `exp_coef`, `se` and `p` (`r/_coxph.py:1360`). The `conf_int` rows in the same dict use `'exp(coef)'`, `'exp(-coef)'`, `'lower'` and `'upper'` (`r/_coxph.py:1386-1388`); R says `lower .95` and `upper .95`. Meanwhile `coefficient_columns` already lists R's names (`r/_coxph.py:1369`).
- **Mixed types.** coxph, survreg and aareg summaries are plain dicts; the survfit summary is `SummarySurvfitResult`.
- **anova.** `anova(coxfit)` returns the native `survival._survival.AnovaCoxphResult` with a default `<... at 0x...>` repr. `anova(survreg...)` returns `SurvregAnovaResult`, whose `loglik` holds -2·LL (repro: `[2303.79, 2294.11]`; `r/_survreg.py:314-321`). `anova(coxfit, test='none')` raises `ValueError: test must be 'Chisq' or None` (`r/_coxph.py:2907`), while survreg accepts it.
- **Attribute names.** `CoxphModel.coef_names` versus `SurvregModelResult.coefficient_names`.

**(a) 3.0 end state:**
- `summary_coxph`, `summary_coxph_penal`, `summary_survreg`, `summary_aareg` and `summary_cch` return frozen dataclasses with attribute access and read-only `["key"]` access.
- Components keep R's names and meanings: survreg `coefficients` is the named vector (a dict from name to value) and `table` holds the rows.
- Every table row uses R's column names (`'exp(coef)'`, `'se(coef)'`, `'Pr(>|z|)'`, `'lower .95'`).
- coxph and survreg share one `AnovaResult` type: column-oriented, R column names, `frame()`, readable repr, and `neg2loglik` in place of `loglik`.
- `coefficient_names` on every model.

**(b) 2.x prep (additive):**
- Add `'table'` to the survreg summary. Return the summary as a `dict` subclass that warns on `['coefficients']`, with a FutureWarning: "summary(survreg)['coefficients'] holds the coefficient table; in survival 3.0 it will hold R's named coefficient vector. Use ['table'] for the table."
- Give rows both the R keys and the old keys. Reading an old key warns: "summary row key 'exp_coef' is deprecated and will be removed in survival 3.0; use 'exp(coef)'."
- Add `SurvregAnovaResult.neg2loglik`. `loglik` warns: "SurvregAnovaResult.loglik holds -2*log-likelihood; it is deprecated and will be removed in survival 3.0; use neg2loglik."
- Accept any non-Chisq `test`, as R does.
- Give `AnovaCoxphResult` a `frame()` and a repr.
- Add a `CoxphModel.coefficient_names` alias.
- Annotate the dict summaries with TypedDicts.

**(c) Affected:** Python users of summaries and anova. R bridge: it reads these dicts (`bridge.R:829,9199-9203,10340`), lockstep. Rust: none.

**(d) Size:** M. Files: `r/_coxph.py`, `r/_survreg.py`, `r/_aareg.py`, `r/_cch.py`, `r/_models.py`, the `print_summary_*` modules, `bridge.R`, tests.

**(e) R fidelity:** improves it.

## C6. Non-R or misnamed public helpers

**Status:** needs a break (removals and renames).

**Evidence:**
- **Three incompatible `totimeline`s:**
  - `survival.r.totimeline(start, stop, status, *, states, id, ...)` (`r/_surv.py:888`), also at the root (`__init__.py:174`);
  - `survival.data_prep.totimeline(id, time1, time2, status, istate)`;
  - the bridge's `totimeline(formula, data, id, istate)` (`bridge.R:3872`, `NAMESPACE:105`).

  R keeps `totimeline` as an unexported draft (`R/fromtimeline.R:242`).
- **`predict_terms_constant`** (`r/_coxph.py:2189`; used at `bridge.R:1477-1480`). Repro: it returns 6.0373 for a survreg fit, where R's attribute is NULL. `predict(fit, type='terms')` returns a plain `list`, which cannot carry a `constant`.
- **`survfit_residuals`** breaks the `<generic>_<class>` pattern of `median_survfit`, `quantile_survfit` and `aggregate_survfit`.
- **Bridge duplicates.** survivalr exports `cox_zph` and `coxph_detail` next to `cox.zph` and `coxph.detail` (`NAMESPACE:39-46`; `bridge.R:8939,8954`).

**(a) 3.0 end state:**
- `totimeline` is gone from the root, `survival.r` and survivalr; one kernel stays in `survival.kernels`.
- Terms predictions carry `.constant` (absent for survreg, as in R), and `predict_terms_constant` is removed.
- `residuals_survfit` is the only spelling.
- survivalr exports only R's names.

**(b) 2.x prep:**
- Add `residuals_survfit`. `survfit_residuals` warns: "survfit_residuals is deprecated and will be removed in survival 3.0; use residuals_survfit."
- Return terms predictions as a list subclass with `.constant`. `predict_terms_constant` warns: "predict_terms_constant is deprecated and will be removed in survival 3.0; use predict(fit, type='terms').constant."
- `survival.r.totimeline` warns: "survival.r.totimeline is an unexported R draft and will be removed in survival 3.0; use survival.data_prep.totimeline."
- The bridge's `cox_zph`, `coxph_detail` and `totimeline` call `.Deprecated`.

**(c) Affected:** Python users of these names. R bridge users who call `cox_zph()`, `coxph_detail()` or `totimeline()`. Rust: `totimeline_py` goes with C18.

**(d) Size:** S. Files: `python/survival/r/__init__.py:445,479,486`, root `__init__.py` and `.pyi`, `r/_surv.py`, `r/_coxph.py`, `r/_survfit_residuals.py`, `r/survivalr/NAMESPACE`, `bridge.R`.

**(e) R fidelity:** improves it.

## C7. Duplicate `pspline` spelling and the unknown-keyword error type

**Evidence:**

- Additive: route `summary_*`, `print_*`, `model_summary` and `nsk` through `_pop_dotted_keyword` (`r/_coerce.py:1013`).

**(c) Affected:** Python users of `boundary_knots=`, and code with `except ValueError` around coxph. R bridge: lockstep. Rust: none.

**(d) Size:** S. Files: `r/_misc.py`, `r/_coxph.py`, `bridge.R`.

**(e) R fidelity:** no effect.

## C8. Result class names

**Status:** needs a break (renames).

**Evidence:**
- Repro: the only case-insensitive collision in `survival.r.__all__` is `CoxSurvFitResult` (`r/_coxsurv.py:30`, the `coxsurv.fit` result) versus `CoxSurvfitResult` (`r/_types.py:777`, `survfit.coxph`).
- Casing is mixed: `CoxPHDetailResult`, `CoxZPHResult` and `SurvDiffResult` versus `SurvfitResult` and `CoxphModel`; `SurvregModelResult` and `AaregModelResult` versus `CoxphModel` and `ClogitModel`.
- `YatesModel` is an input adapter, not a fit.

**(a) 3.0 end state:** one rule: the R function name without dots, capitalized, plus `Result` (or `Model` for fits). Examples: `CoxsurvRawResult`, `CoxphDetailResult`, `CoxZphResult`, `SurvdiffResult`, `SurvregModel`, `YatesFitAdapter`. A script produces the full list for review. Rust struct names are not renamed.

**(b) 2.x prep:**
- Add the new names as aliases of the same classes, so `isinstance` keeps working.
- Serve the old names through `survival.r.__getattr__` and the root `__getattr__`, warning: "survival.r.CoxSurvFitResult is deprecated and will be removed in survival 3.0; use CoxsurvRawResult (the coxsurv.fit result; CoxSurvfitResult is survfit.coxph)."
- In 3.0, keep private module-level aliases so that old pickles still load.

**(c) Affected:** Python imports, annotations and `isinstance` checks. R bridge: it matches reticulate class paths (`bridge.R:6502,9905,9909`), lockstep. Rust: none.

**(d) Size:** M. Files: `r/_types.py`, `r/_coxsurv.py`, `r/_yates_model.py`, `r/__init__.py`, root `__init__.py` and `.pyi`, `bridge.R`, tests.

**(e) R fidelity:** no effect.

## C12. Raw kernels and the R facade share 62 names

**Status:** needs a break.

**Evidence:**
- Repro: 62 names in a core domain module's `__all__` are also in `survival.r.__all__`, and only 4 of them are the same object. By module: regression 13, population 12, surv_analysis 12, validation 10, data_prep 9, core 2.
- For example, `surv_analysis.survdiff(time, status, group, ...)` versus `survival.survdiff(response, data, ...)`.
- `population.PyearsResult` is native (`builtins`), while `survival.PyearsResult` is `survival.r._types.PyearsResult`.
- README.md:471,484-490 presents the domain modules as the algorithm API.

**(a) 3.0 end state:**
- The root and `survival.r` are the R API.
- `survival.kernels` (flat, with a generated `.pyi`) holds every core kernel binding.
- The 58 colliding names exist only in `survival.kernels`.
- Non-colliding kernel names stay in the domain modules as aliases. The extras modules are unchanged, and `survival.core` keeps the typed inputs that extras use.
- A wider variant (every core kernel leaves the domain modules) is not recommended now.

**(b) 2.x prep:**
- Add `survival.kernels` (additive; same objects) and point the README and docs at it.
- Serve the 58 colliding names through module `__getattr__`, warning: "survival.surv_analysis.survdiff is a raw kernel and will be removed from survival.surv_analysis in survival 3.0; use survival.kernels.survdiff, or survival.survdiff for R's survdiff(formula, data)."
- `scripts/generate_stubs.py` emits `kernels.pyi`. This also fixes mypy being unable to see the domain modules (audit python-top #4).

**(c) Affected:** Python users of the colliding domain names, and star-imports. R bridge: about 24 kernel lookups through `.regression_attr`, `.population_attr` and similar (`bridge.R:16-121`) move to `.kernels_attr`, lockstep. Rust: none.

**(d) Size:** L. Files: `python/survival/{core,data_prep,population,regression,residuals,surv_analysis,validation}.py`, a new `kernels.py`/`.pyi`, `_binding_utils.py`, `_binding_manifest.py`, `scripts/generate_stubs.py`, `bridge.R`, README, docs, tests.

**(e) R fidelity:** no effect; R names stop being ambiguous.

## C18. PyO3 wrappers in the public Rust API (with C17's Rust side)

**Status:** needs a break for Rust crate users.

**Evidence:**
- The public core modules re-export 79 `#[pyfunction]` wrappers named `*_py`, 75 of them ungated: surv_analysis 19, validation 30 (about 9 of them extras such as `life_table_py` and `rmst_comparison_py`), data_prep 13, regression 9 (`src/regression/mod.rs:45,47,72,75,93,94,117`), population 7, interval 1.
- Only `cox_zph_py`, `cox_zph_smooth_py` and two validation wrappers are behind `cfg(feature = "python")` (`mod.rs:55-59`). The rest compile against `pyo3_shim` in Rust-only builds.
- `cch` and `cch_borgan` take positional `Vec`s and a string method.
- `#[path]` aliases (`mod.rs:1-2`).
- The crate is published on crates.io (README.md:3), and CI runs cargo-semver-checks (`.github/workflows/semver.yml:16`).

**(a) 3.0 end state:**
- The `#[pyfunction]`s are `pub(crate)` in `src/api/python`.
- The public Rust API is the typed functions (`CoxPHFit::fit`, `aareg_fit(AaregData, AaregOptions)`, and `cch(CchData, CchOptions)` with an enum method).
- `AgexactFit` and `agexact_fit` are removed (C17).
- Plain `mod` declarations replace the `#[path]` aliases.

**(b) 2.x prep:**
- Mark the core re-exports with `#[deprecated(since = "2.1.0", note = "PyO3 wrapper; removed from the public Rust API in 3.0; use <typed fn>")]`, and add `#[allow(deprecated)]` in `src/api/python`.
- Add `CchData`, `CchOptions` and the typed `cch` next to the old one.
- The 9 extras wrappers in `validation` are the owner's call.

**(c) Affected:** Rust crate users only. Python and the bridge are unaffected.

**(d) Size:** L. Files: `src/{regression,data_prep,validation,population,surv_analysis,interval}/mod.rs`, their binding files, `src/api/python/**`, `src/regression/cch.rs`.

**(e) R fidelity:** no effect.

## C19. Only `ml` is feature-gated

**Status:** needs a break for Rust users who build with `default-features = false`.

**Evidence:**
- `Cargo.toml:59-63` has `default = []`, and `src/lib.rs` gates only `ml`.
- About 27k lines of extras always compile: causal 7.2k, interpretability 5.4k, bayesian 3.1k, spatial 2.5k, joint 2.1k, recurrent 1.8k, missing 1.4k, relative 1.3k, reliability 0.9k, monitoring 0.9k, qol 0.7k. More extras sit inside `regression` and `validation`.

**(a) 3.0 end state:**
- One feature per extras family under an `extras` umbrella that is on by default. Default builds and wheels keep everything, which follows the owner's rule. `ml` stays opt-in.
- `--no-default-features` builds the R core only.

**(b) 2.x prep:** add `extras` to `default` as a no-op feature, and document that in 3.0, `default-features = false` drops the extras.

**(c) Affected:**
- Rust: crates that set `default-features = false`.
- Python: none, as long as wheel builds keep the default features.
- CI: `rust.yml:49,57` (`--no-default-features`) would then test only the core, so add an extras job.

**(d) Size:** M. Files: `Cargo.toml`, `src/lib.rs`, `src/regression/mod.rs`, `src/validation/mod.rs`, gated registration in `src/api/python/*`, the Python extras modules (must tolerate missing names, as `ml` does), CI.

**(e) R fidelity:** no effect.

**Recommendation:** defer. The only gain is core build time, and the owner wants the extras left alone.
